# Compatibility and release policy

The launch policy accepted in [#10](https://github.com/jojeringnax/airwallex-laravel/issues/10) requires Laravel 12, Laravel 13, SQLite and MySQL. GitHub records actual qualification and delivery; the matrix below defines the required release boundary.

| Concern | Launch target |
| --- | --- |
| Package / namespace | `jojeringnax/airwallex-laravel` / `Jojeringnax\AirwallexLaravel` |
| License / numbering | MIT; semantic versioning |
| PHP | 64-bit 8.3, 8.4 and 8.5 (`>=8.3 <8.6`) |
| Framework | Laravel 12.69+ (`^12.69`) and 13.30+ (`^13.30`); Testbench 10 and 11 respectively |
| Database | SQLite >=3.43.2 or MySQL >=8.4.11 <8.5 LTS; foreign keys enabled; exact case/Unicode/trailing-space identities |
| SDK | Packagist `jojeringnax/airwallex-php-sdk:^0.1.3`; floor v0.1.3 source `33881b46d696435dfbd370ec371e1fef5452ba44`, including Coupons, Credit Notes, transactions and object-preserving views |
| HTTP / cache | Guzzle `^7.15.2`, PSR7 `^2.13` PSR-18/17; Laravel array/file cache via PSR-16 v3; no token or HTTP behavior duplicated |
| Development / qualification | PHPUnit `^11.5.50`; Composer 2.11.2 with advisory blocking and locked-graph audit |
| Queue | Laravel sync/database queues; database receipts remain recoverable after dispatch/worker failure |
| Package / billable keys | ULID package IDs; integer/UUID/ULID morph keys stored exactly as strings |
| Provider time / quantity | Timezone-bearing text preserves precision/offset; SDK-decoded decimal strings, never floats |

SQLite's floor is the oldest exercised engine, 3.43.2. MySQL's floor is the exercised 8.4.11 server, with InnoDB, 16KiB pages, DYNAMIC default row format, foreign keys and strict SQL mode enabled. The migration checks these prerequisites before creating package tables. MySQL tables explicitly use `utf8mb4_0900_bin` (NO PAD); environment uses a bounded ASCII column so the full 255-character organization/morph/key composite fits the 3072-byte index limit. Nondefault page sizes/row formats, MySQL 8.0/9.x, MariaDB and other engines require separate qualification. Opaque IDs retain Unicode codepoints and trailing spaces; local ULIDs use their canonical fixed-length representation. Large encrypted and JSON payloads use LONGTEXT on MySQL. [MySQL row formats](https://dev.mysql.com/doc/refman/8.4/en/innodb-row-format.html), [index limits](https://dev.mysql.com/doc/refman/8.4/en/innodb-limits.html) and [binary collations](https://dev.mysql.com/doc/refman/8.4/en/charset-unicode-sets.html) define these engine requirements.

[Laravel 13 supports PHP 8.3–8.5](https://laravel.com/framework/docs/13.x/releases); [Testbench 11](https://github.com/orchestral/testbench/blob/11.x/composer.json) supplies its package harness and Testbench 10 serves Laravel 12. All three PHP lines are valid for both declared framework majors. Array/file caches and sync/database queues form the qualified backend set, including their four combinations. Additional drivers require their own infrastructure and evidence.

The adoption programme adds a selected deterministic database-queue/database-cache/database-lock profile on the same qualified database, with explicit package queue connections while the application default is different. `QueueRecoveryTest` exercises that profile in every existing CI cell, and the exact-archive native consumer runs its jobs through real Laravel workers. Record the actual candidate's results before claiming qualification; these synthetic fixtures do not establish the downstream deployment's runtime, supervisor or multi-host topology. Applications verify their own deployment profile; their runtime upgrades are outside package qualification. Redis/SQS are not added by this change.

Fresh consumers obtain the tagged SDK through Packagist, with no path repository/sibling checkout. Development locks capture exact resolutions; package archives omit that root lock. Test lowest/latest allowed dependency sets on each PHP line, including real registration, config caching, migrations, executable recipes and deterministic failures. Qualification uses Composer 2.11.2 with its default security-aware resolver: lowest means the lowest permitted graph that passes current advisory policy, not an insecure historical graph. The direct floors above exclude known affected Laravel/Guzzle/PHPUnit versions; the Laravel 13.30 floor follows the [framework security advisory](https://github.com/laravel/framework/security/advisories/GHSA-jh5r-qr3c-85q8) and the actual audited lowest consumer graph; transitive dependencies still require resolution and audit. The security-aware resolution policy is accepted in [the support issue](https://github.com/jojeringnax/airwallex-laravel/issues/10#issuecomment-6768780428).

Run `composer validate --strict`, `composer check` (deterministic tests, style and static analysis), and `composer check:dependencies` (locked-graph advisory audit) in the repository. CI runs 24 cells: PHP 8.3/8.4/8.5 × Laravel 12/13 × SQLite/MySQL 8.4.11 × lowest/latest. Each cell runs package, style, static, advisory, actual process-race and queue/cache checks plus a fresh exact-archive native consumer. It retains development and consumer locks, actual engine/framework versions, installed recipes and manifests. Development graphs exercise default SDK array views; native consumers select released SDK v0.1.3 with `--preserve-sdk-objects` across both resource families. Coupons and Credit Notes execute in this same released baseline rather than a separate development-extension matrix. CI pins Ubuntu 24.04 and bounds jobs to 45 minutes. The locked advisory audit retries only Composer exit 100 accompanied by a transient curl connection error, for at most three total attempts; advisory/configuration failures and tests are never retried by that helper. Record actual candidate results; new advisory findings require remediation or a separately recorded decision rather than suppressing the audit.

During 0.x, breaking public changes require a new minor, release notes and migration guidance. Patches preserve documented public behavior. Maintain only the latest minor; 1.0 readiness and any broader maintenance promise require a separate decision. Public surface includes documented methods/parameter names, model fields, configuration, payload semantics and exceptions.

[Owned Invoice credits](contracts.md#owned-invoice-credits), Coupon orchestration and Invoice transaction reads use the normal released SDK baseline. Earlier v0.1.1/v0.1.2 profiles are historical evidence and no longer supported dependency resolutions. Existing encrypted Operations and their observation column preserve their command identities through the dependency upgrade.

## Release evidence

Mandatory gates: verified provider/SDK contracts; accepted scope implemented; meaningful deterministic real-SDK tests and independent review; full declared runtime/database/cache/queue/lowest-latest checks; actual file-database races; executable consumer recipes; clean artifact installation/discovery/config cache/migrations; archive exclusions, license/security/release notes; reproducible exact candidate and limitations. Unimplemented requirements or failing required validation remain incomplete.

Sandbox journeys are supplemental under this accepted policy. Run only with explicit sandbox selection, external credentials, authorized organization/entity/collector/source mappings, resource ownership and cleanup controls. Otherwise verify guards and list exact unexecuted journeys. Deterministic fixtures establish package behavior, never provider entitlement, charge success, settlement or production readiness. [Provider evidence](provider-contracts.md) owns account prerequisites and unknown behavior.

A candidate may retain explicitly documented non-blocking upstream limitations, including [SDK representation #37](https://github.com/jojeringnax/airwallex-laravel/issues/37). Awaiting-merge implementation remains open. Preparing/pushing branches and PRs does not authorize merging, default-branch pushes, tags or release publication.
