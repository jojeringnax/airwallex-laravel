# Public interfaces and persistence contract

This reference describes the released implementation contract and explicitly identified adoption interfaces. Accepted invariants are in [scope](scope.md); public choices are accepted under [#34](https://github.com/jojeringnax/airwallex-laravel/issues/34), support under [#10](https://github.com/jojeringnax/airwallex-laravel/issues/10), and provider facts under [provider contracts](provider-contracts.md). The [consumer guide](usage.md) links executable recipes; [release qualification](compatibility.md#release-evidence) defines their evidence requirements.

## Consumer API

Applications authorize the local billable first. Any persisted Eloquent model uses `Jojeringnax\AirwallexLaravel\Billable`; keys may be integer/UUID/ULID and morph maps remain effective. Methods do not assume an authentication guard. `airwallexProfile(): array` is overridable and returns provider customer profile keys; saving a model never syncs remotely.

```php
$customer = $team->createOrGetAirwallexCustomer('customer-command-123', ['name' => 'Team']);
$customer = $team->linkAirwallexCustomer($remoteCustomerId);
$customer = $team->syncAirwallexCustomer('profile-command-124', ['email' => null]);

$subscription = $team->newSubscription('default', $priceId)
    ->quantity(5)->trialDays(7)->startsAt('2026-12-01T00:00:00Z')
    ->create('subscribe-command-125', ['collection_method' => 'AUTO_CHARGE', 'payment_source_id' => $sourceId]);
$checkout = $team->newSubscription('support', $supportPriceId)
    ->quantity(2)->checkout('checkout-command-126', ['success_url' => $successUrl, 'back_url' => $backUrl]);
return $checkout->redirect(); // Explicitly expose the provider HOSTED URL.

$setup = $team->setupPaymentMethod('setup-command-127', ['currency' => 'USD', 'success_url' => $successUrl, 'back_url' => $backUrl]);
$setup->reconcile(); // Verifies checkout and resulting source; does not grant access.
$sources = $team->paymentSources(); // All pages, owned customer/collector.
$checkout->reconcile(); // Verifies resulting subscription under its reserved name.
$checkout->updateMetadata('metadata-command-128', ['reference' => 'support']);
$checkout->cancel('cancel-checkout-command-129'); // SDK action is bodyless.

$subscription = $team->importSubscription('default', $remoteSubscriptionId);
$subscription->updatePaymentSource('source-command-130', $sourceId);
// Explicit action: may immediately retry the provider's last failed invoice.
$subscription->updateQuantity('quantity-command-131', 6, ['default_proration_mode' => 'NONE']);
$subscription->updateQuantity('item-command-132', 3, ['default_proration_mode' => 'PRORATED'], $itemId);
$subscription->swapPrice('swap-command-133', $newPriceId, ['default_proration_mode' => 'PRORATED'], $itemId);
$subscription->addItem('add-command-134', $anotherPriceId, 1, ['default_proration_mode' => 'NONE']);
$subscription->removeItem('remove-command-135', $itemId, ['default_proration_mode' => 'NONE']);
$subscription->updateItems('custom-command-136', [['id' => $itemId, 'quantity' => 3, 'proration_mode' => 'CUSTOM', 'proration_value' => ['charge_amount' => '100.00', 'credit_amount' => '20.00']]], ['billing_action' => 'IMMEDIATE_CHARGE_AND_KEEP_CYCLE']);
$subscription->cancelAtPeriodEnd('ending-command-137');
$subscription->cancelNow('cancel-command-138', 'NONE');
$subscription->reconcile();

$team->subscription('default'); // Current, otherwise latest history for inspection.
$team->subscribed('default'); // Current only, no HTTP.
$subscription->active(); $subscription->onTrial(); $subscription->valid(); $subscription->onGracePeriod();
$invoice = $team->findInvoice($invoiceId);
$invoices = $team->invoices();
$invoice->pdfUrl(); $invoice->hostedUrl(); $invoice->lineItems(); $invoice->lineItem($lineItemId);
$subscription->invoices();
```

For an existing Cashier model, `new AirwallexBillable($authorizedPersistedModel)` exposes these Billing methods through a separate object. It retains the original model's morph class/key and optional `airwallexProfile()` without adding another trait or delegating to its `subscription`, `subscriptions`, `newSubscription`, `invoices`, `findInvoice` or setup methods. The original model keeps all Cashier contracts; returned Airwallex Subscription/Checkout objects retain their package lifecycle/recovery methods. Construct a wrapper after authorization for each request; it does not authorize the model itself. Unsaved models are rejected. [Coexistence usage](usage.md#cashier-coexistence) explains the installed-consumer qualification. No Cashier runtime dependency is added, and the standalone Billable trait remains unchanged.

`newSubscription(name, priceId)` requires a nonempty explicit name. `addPrice(priceId, quantity)` supports multi-item creation. Request quantities are native positive integers under the SDK schema; observed response quantities remain exact decimal strings, including fractional values. Unsupported observed item shapes block unsafe item changes, not otherwise valid lifecycle access. Quantity inputs remain uncoerced until native integer validation; non-strict PHP callers cannot truncate floats. Single-item conveniences fail when the target is ambiguous; multi-item changes require the item ID. Price swaps use deletion plus addition, never an immutable item price update. `swapPrice` accepts an optional final integer quantity after itemId; without it, a fractional/oversized observed quantity is refused rather than truncated. Caller options cannot override mapped customer/context, durable request identity or managed items. `trialDays(days)` uses the final explicit `startsAt` as its anchor, or the intent-preparation time when absent, independently of builder call order. Omit starts_at when the caller does not supply it, preserving the provider default. trialDays produces an absolute trial end at intent preparation; delayed hosted completion does not guarantee that many days after completion. Persist the resulting absolute dates in the prepared intent; repeated action keys reuse them rather than shifting a trial with the clock.

`actionKey` is a stable application command identifier, scoped to immutable billing context. When `createOrGetAirwallexCustomer` finds an already confirmed mapping, it performs a local read: supplied profile values do not sync, a fresh key remains unused, and unrelated mutation holds remain intact. An already-recorded key still validates its original mutation intent and resolves any original ambiguity; use explicit customer sync to update profiles. Persist it in application command handling. Same key/intent returns or recovers the same operation; changed kind/target/payload conflicts. A distinct user-authorized financial action needs a new key. Ambiguous operations throw an actionable exception containing the safe local operation ID; they never silently reissue the write. Customer and Subscription methods return the configured corresponding Eloquent model after canonical verification. `setupPaymentMethod` returns the configured Checkout; `paymentSources` returns a collection of immutable lightweight `PaymentSource` objects (remote `id`, `billingCustomerId`, `linkedPaymentAccountId`, sanitized provider data), with no source table. `updatePaymentSource` returns the reconciled Subscription. Checkout methods return the configured Checkout, invoice reads return immutable lightweight Invoice objects, and list reads return collections after all pages succeed. Unmapped billables return no local subscription; remote operations require a confirmed customer.

Public package exceptions extend `BillingException` (RuntimeException): `ConfigurationException`, `OwnershipException`, `ConflictException`, `EvidenceException` and `AmbiguousOperationException`. Messages contain safe classifications only; `AmbiguousOperationException` exposes readonly string `operationId` and retains only already-redacted SDK exceptions as causes, preserving SDK classification. Untrusted transport/storage/confirmation causes are discarded; default string/debug output excludes traces/arguments and exception serialization is rejected. `ConflictException` may expose a nullable readonly `operationId`; other exceptions need no payload/context dump. SDK exceptions retain their original classification as causes; no secret payloads are added. Raw SDK `Client` is replaceable in the container; `Airwallex` facade resolves it. `BillingContext` is immutable environment/organization; credentials never form database identity. Provider access policy interface is `SubscriptionAccessPolicy::allows(Subscription $subscription): bool`, replaceable through the container. Default lifecycle helpers follow [scope](scope.md), independently of custom policy.

High-level financial workflows use one configured legal entity/collector, as accepted in [#39](https://github.com/jojeringnax/airwallex-laravel/issues/39). Different routing overrides and contradictory returned routing values are rejected. Subscription routing fields are optional; Checkout requires `linked_payment_account_id` but may omit `legal_entity_id`. Missing optional fields alone do not block known actions, reads or correlated recovery. Original request intent, owned canonical resource/customer/context and operation correlation still govern confirmation; timeout or unknown identity never permits replay. Snapshots retain absent fields without filling them from configuration. `observed_routing` separately retains the last positive Subscription routing values across omissions, so a read-only foreign-route import cannot erase a known contradiction and authorize a financial write. A new positive canonical value replaces that field’s prior evidence. Operations separately retain bounded routing values from mutation responses; a previously returned contradiction or malformed value needs positive matching canonical evidence, rather than omission, before recovery can succeed. Entity/collector eligibility and financial outcomes remain provider/account evidence.

Scheduled access uses `scheduled_ends_at`, a local projection copied from positively observed effective-bound dates while the scheduled flag is true. A previous unrelated finite end does not prove a fresh schedule. Retain the earliest confirmed schedule cap across partial reads/rollovers; an explicit false flag resets this schedule projection. Ordinary ACTIVE rollovers still do not cap access. [Question #34](https://github.com/jojeringnax/airwallex-laravel/issues/34#issuecomment-6770070532) records the evidence and data effects.

## Schema ownership

All tables use `airwallex_`; local primary keys are ULID strings. Configured subclasses extend the corresponding package model; the service provider resolves all relationships and service queries through configured classes. Local Laravel timestamps are UTC microseconds. Provider dates/timestamps are exact text with timezone/offset/fraction retained; a chronological comparator handles arbitrary fractional precision. JSON snapshots preserve SDK-decoded unknown fields and decimal strings; populated numeric-key object wire types may already be normalized by the SDK ([#37](https://github.com/jojeringnax/airwallex-laravel/issues/37)), so those ambiguous updates require further proof rather than inferred confirmation; raw owner/profile data and secrets are hidden from normal model serialization.

| Table | Fields and constraints |
| --- | --- |
| `airwallex_customers` | `id`, `environment`, `organization_id`, `billable_type`, `billable_id` (opaque string), nullable `remote_id`, `synced_at`, timestamps. Unique local morph/context and remote/context. Reservation precedes creation. |
| `airwallex_subscriptions` | `id`, `customer_id`, context, `remote_id`, `name`, raw `status`, internal monotonic `revision` for concurrent observations, `starts_at`, `ends_at`, `trial_starts_at`, `trial_ends_at`, `current_period_starts_at`, `current_period_ends_at`, `cancel_at_period_end`, local confirmed `scheduled_ends_at`, `cancel_requested_at`, `provider_created_at`, `provider_updated_at`, sanitized `snapshot`, nullable `observed_routing`, `synced_at`, `items_synced_at`, timestamps. Remote/context unique; owner immutable. Optional date columns retain the last positively confirmed timestamp when later responses omit it or return null; raw snapshots preserve the precise absence/null. A first absent/null observation remains null. This conservative local bound policy is accepted under [#34](https://github.com/jojeringnax/airwallex-laravel/issues/34#issuecomment-6769270411), pending verified clearing semantics. | `airwallex_webhook_receipts` | `id`, trusted context, `event_id`, body digest, `event_name`, version, resource identity, encrypted body, `status`, `attempts`, `last_error`, timestamps. Unique context/event ID; conflicting same-ID bodies quarantined. |

Provider IDs and owner/context cannot be reassigned by a later observation or mass-assigned as a side effect of reconciliation. DB constraints enforce uniqueness; services validate parent/context on every attach. Default database is the application's configured connection; the qualified SQLite/MySQL versions and prerequisites are defined in [compatibility](compatibility.md). Migrations are publishable and reversible; no billable-table changes. Offboarding never automatically deletes history or performs remote cancellation; application retention/authorization decides local deletion after operational and legal review. Customer/subscription deletion is restricted while children/reservations exist.

## Operation, checkout and receipt lifecycles

Operations: `prepared` persisted before I/O, then `in_flight`, then `succeeded`, `failed` (verified no-write rejection), `ambiguous` (unproved request/outcome), or `acknowledged` (known item-write response, requested observable item state not yet proven). Preserve original request/correlation and record returned remote identity before follow-up reads. For eligible item actions only, acknowledged releases the active mutation mutex while preserving exact request/intent/result IDs; same-key calls and recovery read only. Unknown HTTP outcomes stay ambiguous and held. Exact native-integer versus observed decimal quantity proof distinguishes 5.000 from 5.00000000000000001 without floats. New item proof needs fresh owned references and remains unconfirmed while overlapping unresolved item actions make attribution ambiguous; old/new coexistence does not prove removal, active fee or settlement. Later separately authorized actions never authorize replay of the earlier one. [Question #40](https://github.com/jojeringnax/airwallex-laravel/issues/40) records this accepted defensive lifecycle choice. Never hold a DB transaction over network calls. Unique rows and compare-and-set transitions coordinate competing writers. On MySQL, short local transactions lock the owning Customer before reservation/projection reads and retain receipt-lease fences through projection commits; provider I/O remains outside those transactions. An expired worker lease is recovery eligibility, not permission to replay a financial write. Known-ID operations recover through canonical reads; unknown-ID create requires verified metadata correlation or an explicit operator-supplied resource and ownership proof. A 404 or timeout alone cannot release the name. The SDK exposes no checkout list; record the specific upstream automation limit rather than adding Laravel HTTP.

A Checkout reserves its subscription name from intent through confirmed resulting Subscription or verified terminal cancellation/expiry without a resulting resource. Ambiguous terminal evidence retains the reservation. Store actual provider status/expiration; do not invent TTLs. Setup has no name slot and its completed verified source does not change subscription eligibility. Delayed responses and webhooks converge through operation correlation and immutable IDs. Caller metadata is merged with a reserved operation marker; overriding it is rejected.

Receipts: `pending`, `processing`, `processed`, `ignored`, `quarantined`, `failed`. Verify signature with the SDK before persistence; bind trusted receiver context/version; durably store before 200. Foreign owner/version or conflicting identity is quarantined; unknown events/resources are ignored with reason, never adopted. Dispatch failure leaves pending work; scheduled replay finds it. Workers claim receipts atomically and recover expired processing leases. Signature verification occurs on receipt, not replay; replay trusts the already verified encrypted receipt. Purge bodies only for terminal processed/ignored/quarantined receipts after configured retention (default seven days); pending/processing/failed bodies remain recoverable until processed or explicitly quarantined by an operator. Retain identity/digest/outcome for deduplication. A purged receipt cannot be replayed from its body; canonical reconciliation remains available.

Domain events use a stable correlation ID, local resource ID, context and prior/current provider status, never credentials, profile data or URLs. `SubscriptionReconciled`, `CheckoutReconciled`, `InvoiceObserved` and `WebhookProcessed` are persisted in `airwallex_domain_events` in the state-change transaction, then dispatched after commit. A failed dispatch or crash between commit and dispatch leaves the outbox row undispatched; the scheduled event command retries it. A crash after listener delivery but before marking dispatch can redeliver the same stable ID. Outbox delivery is at least once; application listeners deduplicate stable IDs and reconcile if delivery was interrupted. For Laravel ShouldQueue listeners, outbox acknowledgement means successful queue handoff, not eventual listener completion; Laravel queue retry/failed-job handling owns that separate stage. No exactly-once financial/listener promise is made.

## Operational API

Operational commands and their exact options are defined in [webhooks and recovery](operations.md#bounded-commands). Each uses bounded batches, context filtering and safe progress identifiers. Recovery never submits prepared intents or repeats remote mutations. Inspect acknowledged item effects separately from unknown HTTP outcomes. Operator candidate association for unknown-ID subscription/checkout creation still requires canonical identity, customer, routing and reserved metadata proof. Queue workers, listener idempotency, scheduling, body retention and offboarding procedures are in the same reference.

## Adoption amounts and provider routing

`Subscription::scheduleTransition(actionKey, effectiveAt, items, options, expiresAt)` stores a single pending item transition for the current subscription generation. Effective/expiry times are exact timezone-bearing strings; expiry is an explicit allowed execution window, not a provider timing promise. Options require explicit proration and billing action. The stored source shape includes item identities/prices/quantities, source/collection and auto-renew bounds. `SubscriptionTransition::cancel()` or `replace(actionKey, effectiveAt, items, options, expiresAt)` works only before execution starts; replacement is one local transaction. `run()` and `airwallex:transitions` execute due work once using a stable internal command; resumed attempts use canonical recovery. A changed source generation/shape, unconfirmed ACTIVE state or missed window blocks the plan for an explicit new decision. Prepared future plans do not acquire the subscription financial mutex; execution shares the ordinary mutation mutex. One plan per generation remains reserved through ambiguous writes. Free-period commercial rules remain application-owned: IN_TRIAL may have a due downgrade after its confirmed trial end, while an ACTIVE billing holiday has no invented trial-extension implementation. Exact provider-boundary and arbitrary multi-phase parity remain unclaimed under [SDK #161](https://github.com/jojeringnax/airwallex-php-sdk/issues/161).

`Subscription::restoreRenewal(string $actionKey, string $scheduleActionKey): Subscription` restores a pending cancellation using the exact original finite end saved by that package scheduling action. The supported combination is ACTIVE, OUT_OF_BAND, a future finite original end and no payment source; indefinite, AUTO_CHARGE, trial, UNPAID and already-CANCELLED combinations require stronger provider evidence. Old/imported scheduled records without a saved pre-scheduling bound are ineligible. Scheduling intents retain exact original field presence/values before their first write. Restoration has its own stable action/request ID and targets the same local/remote subscription generation. A canonically observed false flag and exact original end are required before clearing its scheduled access cap. Ambiguous restoration keeps the cap and command; recovery reads and never resubmits. [SDK timing evidence](https://github.com/jojeringnax/airwallex-php-sdk/issues/158) and [open confirmation](https://github.com/jojeringnax/airwallex-php-sdk/issues/161) own unavailable combinations. This additive adoption API does not change the raw SDK's available fields.

The application boundary converts its integer minor-unit representation to exact decimal strings using an explicitly verified currency exponent; the SDK preserves the resulting major-unit value. For exponent 2, `"12345"` becomes `"123.45"`; exponent 0 retains `"12345"`; exponent 3 becomes `"12.345"`. Conversion uses digit/string operations, never floats, locale formatting or scientific notation. Reject unknown currencies, unsupported exponents, fractional minor units and out-of-range business amounts before command creation; reverse conversion rejects excess nonzero fractional precision rather than rounding. Zero is handled according to the [consumer scope](scope.md#full-provider-adoption-contract), never as invented provider success. The application owns any currency table/version and must verify the selected currency and method with the provider.

Billing organization and Payments account are independent immutable contexts. Separate mapping types, command identities, remote IDs and webhook routes prevent accidental cross-family adoption even where provider IDs have the same spelling. Consumer ledgers key deduplication by provider + environment + owning context + canonical financial resource ID + financial event type, not browser status or webhook event ID alone. Old-provider history/refunds stay routed to their original provider.
