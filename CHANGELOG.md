# Release notes

## 0.2.0 — 2026-11-13

This minor release changes dependency support and creation retry behavior. Publication and the exact tagged source are verified separately on [Packagist](https://packagist.org/packages/jojeringnax/airwallex-laravel). Follow [upgrade guidance](UPGRADING.md#upgrading-from-010) before deployment.

- Requires released SDK `^0.1.3` for Coupons, Credit Notes, Invoice transactions and optional object-preserving views. The normal 24-cell runtime/database/dependency matrix now covers these features; obsolete extension-only coverage and capability refusal are removed. The locked advisory audit has bounded retries for classified network errors, without retrying tests or suppressing advisories.
- Allows a new creation action key after an unknown-ID attempted creation, deliberately permitting provider duplicates. Original commands remain auditable and unknown; same-key writes are never replayed. Late original locators are quarantined. An additive migration preserves merchant-order history while reserving only the current generation. Billing validates local SDK configuration before claiming dispatch.
- Creates Billing Payment Sources from verified, owned Payments instruments using durable commands and read-only ambiguity recovery. Instrument revocation emits observations; a consumer-configured handler can apply an explicit subscription policy. Subscription changes remain opt-in.
- Adds exact trial end timestamps and dated subscription ending with explicit provider financial controls, saved original bounds and guarded restoration. The package computes no proration or automatic refund.
- Adds verified percentage/fixed Coupon application for subscription creation and supported existing-subscription flows. Coupon terms and original Discount evidence are retained; stacking, currency mismatches and undocumented timing assumptions are refused. Provider CUSTOM duration remains calendar-based rather than an invented invoice-count guarantee.
- Adds standalone Payments customers, browser setup, saved instruments, intent confirmation/capture/cancellation, partial/full refunds, signed receipts and durable observations. Billing adds Cashier coexistence, explicit queue connections, persisted sweeps, renewal restoration and deferred transitions.
- Adds owned Invoice transaction reads and three-stage original-Invoice credits. The existing experimental FLAT/ONCE first-charge helper retains its explicit Invoice-attribution and provider-timing limitations. Application ledgers, commercial policy and financial allocations remain consumer-owned.

PHP 8.3–8.5, Laravel 12.69+/13.30+, SQLite and MySQL retain their [declared support boundary](docs/compatibility.md). API/webhook pin `2026-08-21` is unchanged. Deterministic checks establish library behavior and artifact integrity; account-specific Sandbox journeys are supplemental and unexecuted cases remain explicit. Browser/wallet eligibility, actual provider financial effects, settlement and atomic future-boundary guarantees are not inferred.

## 0.1.0 — 2026-11-10

The first Laravel integration provides persisted Billable customer mappings, explicit customer link/subscription import, named multi-item subscriptions, direct and HOSTED checkout creation, SETUP source collection, verified source reads/replacement, explicit item/price/quantity/proration changes and scheduled/immediate cancellation. Browser/setup success grants no independent access; eligibility follows owned canonical subscription state and confirmed bounds.

Signed Billing webhooks use the released SDK verifier/decoder, encrypted durable receipts, context/version checks and canonical reconciliation. Bounded read-only recovery commands and an immutable event outbox handle dispatch/worker failures without mutation replay. Lightweight owned Invoice objects expose complete invoice/line reads and nullable observed PDF/hosted links without a local invoice ledger, downloader or renewal clock.

The package includes extensible model/profile/access-policy interfaces, twelve executable consumer recipes, operational/offboarding guidance and exact-archive installation tooling. [Compatibility](docs/compatibility.md) owns the PHP 8.3–8.5/Laravel 12.69+/13 and SQLite/MySQL support boundary and array/file-cache plus sync/database-queue set. The runtime dependency is released Packagist SDK v0.1.1 at `bd11abb67e2e5761b86a9ca9d4a1b7993900de6e`; selected API and webhook contracts are `2026-08-21`. Final evidence records the actual resolved dependency graph for its exact candidate commit.

Accepted decisions remain explicit: [#10](https://github.com/jojeringnax/airwallex-laravel/issues/10) support/identity/license/distribution policy; [#34](https://github.com/jojeringnax/airwallex-laravel/issues/34) durable command/public behavior and confirmed date bounds; [#39](https://github.com/jojeringnax/airwallex-laravel/issues/39) configured routing and per-resource optional response fields; [#40](https://github.com/jojeringnax/airwallex-laravel/issues/40) known item acknowledgements versus observed fulfillment. [#37](https://github.com/jojeringnax/airwallex-laravel/issues/37) records SDK-decoded representation proof limits. An acknowledged item action is not a settlement/effectiveness guarantee and is never replayed; irreducible ambiguity remains visible.

Deterministic tests and synthetic SDK fixtures establish package behavior. They do not establish Billing activation, account permissions, optional routing-field presence, hosted delivery timing, natural trial/renewal/ending, configured dunning, charge success/settlement, invoice-link renewal/expiry or Sandbox cleanup observations. [Provider evidence](docs/provider-contracts.md) and the supplemental Sandbox evidence record distinguish these gaps. Historical lowest dependencies excluded by current security floors are not supported; an upstream Symfony Translation 6.4.0 PHP 8.4 nullable deprecation remains visible in the allowed lowest test graph.

At this release, standalone Payments/refunds, multiple Billing organizations/connected routing, OAuth, catalogue administration, embedded components, customer portal UI, generic local trials, tax/coupons/usage billing, pause/reactivation and unverified resume/link/PDF/mailing conveniences were deferred. [Scope](docs/scope.md) records current capabilities. Raw SDK capabilities remain accessible within application authorization.

Release qualification and delivery are recorded in the [release tracker](https://github.com/jojeringnax/airwallex-laravel/issues/1). The local `0.1.0-RC1` descriptor remains an exact-commit review archive; registry publication is verified separately. See [upgrade guidance](UPGRADING.md), [security](SECURITY.md) and [reproduction instructions](docs/release.md).
